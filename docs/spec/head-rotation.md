# 頭の3D形状による顔の向き

PoC-08 の分解結果から作ったパーツと、正面の特徴点から、頭の3D形状を作り、顔の向き（`AngleX` × `AngleY`）のキーフォームを、1つの回転と投影で作る仕組み（#39）。斜めの顔の輪郭は、回した輪郭を 2D の目標の線へ寄せて整える（#50）。方法を選んだ理由は [ADR 0011](../adr/0011-face-rotation-by-head-3d-shape.md) と [ADR 0013](../adr/0013-face-outline-by-2d-target-line.md) にある。PoC-10 の推定（[対応づけと変形推定](keyform-estimation.md)）に代わって、`ugokue-pipeline keyforms` で使う。

3D形状は、キーフォームを作るときにだけ使う。中間形式には3D座標を持たせず、実行時は今までどおり2Dのキーフォームを補間する。前後関係は、パーツの描画順とビューの切り替えで表す（[ADR 0010](../adr/0010-defer-per-vertex-depth-ordering.md)）。

## 構成

```mermaid
flowchart LR
    result[分解結果] --> convert[変換<br/>格子のメッシュ]
    convert --> fit[頭の3D形状<br/>顔の層と口の高さ]
    landmarks[正面の特徴点] --> fit
    fit --> turn[パーツの付き方ごとに<br/>回して投影]
    convert --> turn
    turn --> outline[輪郭を2Dの<br/>目標の線へ寄せる]
    outline --> keyforms[キーフォーム]
    keyforms --> sheet[比較シート<br/>生成した向きの絵と並べる]
```

| 場所 | 役割 |
| --- | --- |
| `pipeline/python/src/ugokue_pipeline/head3d.py` | 頭の3D形状（`HeadShape`）、当てはめ（`fit_head`）、パーツの付き方（`Attachment`、`attachments_for`）、回転と投影（`turn`）、キーフォームの作成（`build_keyforms`、`apply_keyforms`） |
| `.../keyforms.py`、`cli.py` | イラストごとにモデルを作り、比較シートと評価を書く `ugokue-pipeline keyforms` |
| `.../evaluate.py` | 中間の角度での三角形の品質 |
| `head3d.py` の `HeadParams`、`keyforms.py` の `load_params` | イラストごとの形の値（`params.json`） |

GPU は使わない。

## 頭の3D形状

画面の行 y ごとに、断面（中心 c、半幅 w、前面の奥行き h、板の割合 k）を持つ。断面は、前を半幅 k × w の平らな板にし、板の外を楕円の 1/4 の角で丸めた形（k が 0 なら楕円で、角度 φ（右の輪郭で 0、正面で π/2、左の輪郭で π）の点は x = c + w cos φ、z = h sin φ）。奥行き z は、回す中心の面から手前が正（画素）。

当てはめ（`fit_head`）：

1. 顔の層（See-through が髪の下に補完した頭皮を含む）の不透明な画素から、行ごとの左端と右端を取り、中心と半幅にする。顔の層の高さの 2% の幅でならす。
2. 頭の半径 r は半幅の最大。回す中心は、顔の層の箱の中心。
3. 前面の奥行き h は、半幅の 0.8 倍。目（特徴点 `afd_11`〜`afd_22`）の行より下は、目の行の値のままにする（目・鼻・口は1つの面に乗る。正面の輪郭の V 字に合わせて浅くすると、あご先が向いた側へ寄らない）。
4. 口の行（特徴点 `afd_24`〜`afd_27` の平均の高さ）より下は、あごの板にする。半幅は口の行の値のまま、奥行きは口の行の値から、いちばん下の行で 0.75 × r になるよう線形に変える。あごの輪郭（V 字）は横の輪郭ではないので、行ごとの幅で断面を作ると、輪郭の上で奥行きが急に 0 になる。
5. 板の割合 k は、目の行で（目尻の中心からの距離 × 0.8 ÷ 半幅、0.9 まで）にし、口の行までその割合のまま。目より上は目と口の間の長さで、口より下はいちばん下の行までで、cos で細くし、あご先では口の行の半幅 × 0.3 にする。板の幅を一定にすると、顔が細くなる口の高さで角が急になり、輪郭が内へ引き込まれる。
6. 輪郭の目標の線のために、顔の層の行ごとの左右の端（ならしたもの）と、頬のふくらみの強さ（目の行から口の行までの 0.4 の高さで 1、目の行より目と口の間の 0.5 倍上と、いちばん下の行で 0、cos でつなぐ。目の高さでも少しふくらませ、奥の目尻が輪郭に押し付けられないようにする）を持つ。
7. 形の範囲より上や下の行は、いちばん近い端の行の断面にする。

固定テストモデルと同じ形（球を奥行き方向に縮めた楕円体）は、`HeadShape.sphere(中心, 半径, 奥行きの倍率)` で作る。

## パーツの付き方

| 付き方 | パーツ（役割） | 奥行き |
| --- | --- | --- |
| 表面 | 顔 | 断面の上の点 |
| 浮かせた表面（なめらか） | 目（白目、黒目）、まぶた、眉、口、鼻、眼鏡 | 断面の上の点に、浮き（まぶた 0.01、眉 0.02、口 0.005、鼻 0.15、眼鏡 0.08。× r）を足す |
| 殻 | 前髪、頭の飾り、ほかの頭のパーツ | 断面の半幅と奥行きを 0.06 × r 太らせた楕円の上の点 |
| 板 | 耳 | 0（回す中心の面）。手前側では、輪郭の目標の線から、正面での輪郭からの離れ方だけ離す（頭の横が見えてきても、耳が輪郭から浮かない） |
| 奥の板 | 後ろ髪 | −0.3 × r |

- 断面の外の頂点（顔の横に垂れる髪など）は、奥行きを浮きの値にした板として回す。
- **なめらかにする：** 目・眉・鼻・口・眼鏡は、パーツの頂点の3D座標（x と z）を、輪郭の内側の頂点に当てはめた2次式で置き換える。まつ毛の目尻のように輪郭の外に出た頂点で奥行きが急に変わると、三角形が裏返るため。回したあと、パーツの重心の動きはそのままに、形の変化を 0.6 倍に弱める。

## 回転と投影

各頂点を、回す中心のまわりに yaw → pitch の順で回し、正射影する（[固定テストモデル](test-model.md#顔の向きanglex--angley)と同じ式）。

- x' = x cos(yaw) + z sin(yaw)
- y' = y cos(pitch) − (−x sin(yaw) + z cos(yaw)) sin(pitch)

- **左右の軸：** 頭の中心より 0.5 × r 奥の軸（首の付け根にあたる）で回す。頭全体が 0.5 × r × sin(AngleX) だけ向いた側へ動く。
- **上下：** `AngleY` の角度の 0.6 倍だけ回す。前面が深いので、角度どおりでは顔が上下に大きくずれる。
- **輪郭の合わせ直し：** 向いた側（AngleX が正なら画像の右）の断面の点の角度 φ（0〜π/2）を、φ' = φₛ + φ (1 − 2φₛ/π) に詰める。φₛ は、回したときに断面がいちばん外に出る点（外形線）の角度 atan(h sin|yaw| / (w cos|yaw|)) を 1.15 倍したもの（外形線ちょうどでは表面を真横から見るので、輪郭の近くの三角形がつぶれる）。輪郭は外形線の少し内側に来て、向いた側の頬は外形線まで縮み、あご先は向いた側へ寄る。反対側（手前に回ってくる側）は変えない。
- **輪郭の外の頂点：** 向いた側の輪郭の外の頂点（顔の横に垂れる髪）は、輪郭の合わせ直しで輪郭が動いたぶんを、輪郭からの距離 d に応じて exp(−(d / (0.15 × r))²) 倍だけ足す。耳（板）には足さない。耳は回す中心の面にあるので、向いた側の耳は輪郭の内側へ動き、顔の下に隠れていく。
- **手前側の並べ直し：** 反対側（頭の横が回ってくる側）は、中心から 0.3 × w より外の頂点の x を、その点を回した位置から輪郭の点を回した位置まで、3次の曲線で並べ直す。曲線の比は、内側の端で板の上の比（cos yaw）、輪郭で 1 にする（輪郭に描かれた線を太らせない）。頭の横が回ってきて広がるぶんは、範囲の中ほどに散る。輪郭の外の頂点は比 1 で延ばす。口の行より下は、断面の半幅が口の行のままで描かれたあごより広いので、描かれたあごの端を輪郭にする（断面の半幅を使うと、あごの縁の外の頂点が輪郭へ押し付けられ、描かれた輪郭の線がつぶれて途切れる）。描かれたあごの半幅が断面の半幅の 0.5 倍より細くなると、あご先へ向かって並べ直しを弱める（細い範囲で並べ直すと、伸びが急に変わる）。板の外の角は急なので、そのまま回すと輪郭のすぐ内側が大きく内へ引き込まれ、三角形が大きく伸びて輪郭の線がにじむ。比が折れると、粗いメッシュの細長い三角形が折れをまたぎ、縁が階段状になる。
- **輪郭の目標の線（2D）：** 目・眉・鼻・口以外の頂点を、行ごとの目標の線へ寄せる。基の線は、顔の層の左右の端を上の式で回した位置。目標の線は次のように作る。
  1. 基の線を、縦に 0.1 × r の幅でならす。
  2. 向いた側には、頬のふくらみ 0.2 × r × sin|yaw| × 頬の強さを外へ足す。
  3. 反対側には、半幅 × (hypot(cos yaw, 0.8 sin yaw) − cos yaw) を外へ足す。頭の横（奥行きが半幅の 0.8 倍の楕円）が回ってきて外形線になるため。
  4. 足し合わせた線を、もう一度縦に 0.1 × r の幅でならす（頬のふくらみや頭の横の張りのつなぎ目の角をなくす）。
  5. 向いた側の、頬のいちばん張った行（頬のふくらみのある、口の行より上の行で、線がいちばん外の行）から口の行までを、次のあごの線の奥側の曲線の上に置く（`jawRound` の割合だけ近づける）。行ごとに作ると、頬から口の行まで斜めの直線になり、その下のあごの線が外へふくらんでから回り込む S 字になる。

  目標 − 基 を、その側の頂点に、輪郭からの距離 d に応じて、内側は exp(−(d / (0.3 × r))²)、外側（耳、髪）は exp(−(d / (0.8 × r))²) 倍だけ足す。それぞれの倍率は `params.json` の `contourSmoothing`、`chinPlate`、`cheekBulge`、`jawRound`（あごの線に近づける割合、既定 1）、`nearFullness` で変えられる。
- **あごの線（2D）：** 口の行より下は、行ごとの線ではなく、2D の曲線であごを作る。あごの輪郭は横の輪郭ではなく下へ回り込むので、行ごとの左右の端では、あご先の丸みと位置を書けない。
  1. 基の線は、顔の層の口の行より下の縁（奥側の口の行からあご先の底の行を通り、手前側の口の行まで）を回した折れ線。底の行にも1画素ごとに点を並べる（左右の端だけだと、底の間の頂点が近いほうの端の動きになり、底の中ほどに段ができる）。
  2. 目標の線は、あご先の点（回したあご先の中心の x、いちばん下の行）へ向かう2本の3次ベジェ曲線。
     - 奥側は、頬のいちばん張った点から始まり、口の行より下の部分を使う。始まりは、その点の上 0.15 × r で測った傾き（外へ向かう傾きなら真下）で、制御点は端点間の距離の 0.5 倍。あご先の側の制御点は置かない（あご先へ斜めに入る）。頬でいちばん張った点から、向きを戻さずにだんだん強く内へ曲がる、楕円の 1/4 に近い形になる。レビュー役が描いた修正の線との距離で、制御点の長さを選んだ（あご先の側を長くすると、あごの底が平らで四角くなる）。
     - 2本をつないだ線を、線に沿って 0.06 × r の幅でならし、あご先で2本が合わさる角を小さな丸にする。
     - 手前側は、口の行の目標の点から始まり、口の行より上（0.15 × r）で測った輪郭の傾きを保つ（口の行で折れない）。制御点は端点間の距離の 0.5 倍で、あご先では横向きに、0.3 × 口の行の半幅 × cos yaw（`chinPlate`）の制御点で入る。
  3. 基の線と目標の線の点は、線の長さに対する割合で対応させ、`jawRound` × (目標 − 基) を、いちばん近い基の線の点から、輪郭からの距離で上と同じように弱めて足す（内か外かは基の線で囲んだ形で決める）。
  4. 口の行の上下 0.075 × r で、行ごとの寄せからあごの線の寄せへ線形に切り替える。
- **首：** 首のメッシュにも顔の向きのグループを置く。あごの行より上は頭と一緒に回し、メッシュの下端に向かって追従を線形に 0 にする。上下は、あご先と同じ奥行きで回す（上を向いても、あごの下から首の上端が見えない）。左右は回す中心の面で回す（あご先と同じだけ横に動くと、首が大きくゆがむ）。
- **ならし：** 表面に付くパーツ（顔、前髪、頭の飾り）は、正面以外の格子点で、移動量を1回ならす（[対応づけと変形推定](keyform-estimation.md#頂点の移動量)の `solve_offsets`）。ならすのは描かれている部分の内側の頂点だけで、パーツの輪郭（描かれている三角形と透明な三角形の境、メッシュの外周）とその外の透明な頂点は、元の動きを 30 倍の強さで守る。輪郭の合わせ直しで輪郭の近くにたまる伸びを内側に散らし、輪郭の形は目標の線のまま保つ。
- **裏返り：** 格子点で三角形が裏返ったら、移動量をならして解き直す（`solve_without_flips`）。元の動きを守る強さは、裏返った三角形の頂点からの距離 d で exp((d / (0.6 × r))²)（1000 まで）にし、ならすパーツでは輪郭を守る強さと大きいほうにする。メッシュ全体をならすと、手前側の輪郭が内へ引き込まれ、耳が浮く。

格子は、`AngleX` が −45〜45 の 15° おき、`AngleY` が −20、0、20。モデルの `AngleX`、`AngleY` の範囲を格子に合わせて広げる。

## 実行のしかた

PoC-08 の `decompose_images` の結果（`artifacts/decomposition/`）と、PoC-09 の特徴点（`artifacts/views/<イラスト名>/landmarks.json`）があれば、リポジトリのルートで実行できる（GPU 不要、dotnet が必要）。

```bash
uv run --project pipeline/python ugokue-pipeline keyforms
```

`--names 01-long-straight` で一部だけを処理する。形の値（このページの倍率）は、`artifacts/keyforms/<イラスト名>/params.json` でイラストごとに変えられる（[エージェントによる顔の向きの判定](agent-review.md#イラストごとの値paramsjson)）。結果は `artifacts/keyforms/<イラスト名>/` に、`model/`（中間形式）、`renders/`（格子の各向きで描いた絵）、`evaluation.json`、`sheet.png` として書く。

- `sheet.png`：上向き・正面・下向きの行ごとに、−45〜45° の各向きで描いたモデルを並べる。その下の行には、PoC-09 で生成した向きの絵があれば同じ列に並べる（確認用。大きさと傾きはそろえていない）。
- `evaluation.json`：検証の結果、使った形の値（`params`）、頭の3D形状（中心、半径、行の数）と、`AngleX` −45〜45、`AngleY` −20〜20 を 5° おきに変形したときの三角形の品質（[評価](keyform-estimation.md#評価)の `quality` と同じ項目）、引き継げなかった手の修正のグループ（`droppedEdits`）。
- **手の修正の引き継ぎ：** `model/` に前のモデルがあれば、Unity エディタで作った手の修正のグループ（`<メッシュ>_angle_edit`。[キーフォームの手の修正](runtime-deformation.md#キーフォームの手の修正エディター)）を、作り直したモデルに引き継ぐ（`carry_edits`）。メッシュの頂点か格子が変わったグループは引き継がない。自動のグループの置き換えは ID で行い、手の修正のグループは消さない。

できたモデルは、プレイヤーを `-ugokue-model artifacts/keyforms/<イラスト名>/model` 付きで起動すると、Unity で動かせる。

- 5枚とも、中間の角度を含めて三角形の裏返りはない。極端な伸び（3 倍超か 1/3 未満）は、顔の層の縁と、前髪・頭の飾り・眼鏡のつるの、向いた側の輪郭の近く（表面が奥へ回り込むところ）と、首の上端に出る。まぶたの極端な伸びは、テクスチャの透明な部分の三角形で、描かれる部分は 0.56〜1.39 倍に収まる。
- 手前の目は 1.1〜1.2 倍に広がる。表面が見る向きに回ってくるため（球の上の目なら 30° で約 1.2 倍）。
- 試作の途中で見つかって直したこと：
  - 眼鏡を前髪と同じ殻にすると、レンズの形が崩れた。目と同じく、なめらかな表面から浮かせた。
  - 上下を角度どおりに回すと、上を向いたときに顔が大きく上がり、首の上端（補完の縁）があごの下に見えた。上下を 0.6 倍にし、首の上下の追従をあご先の奥行きにした。
  - 行ごとの幅であごの断面を作ると、上を向いたときにあごの輪郭がぎざぎざになった。口より下をあごの板にした。
  - 鼻先だけを突き出すと、鼻の線が 0.13 倍まで縮んだ。パーツ全体を前へ出した。
  - 目のくぼみを入れると、奥の目が目頭の側で強く縮んだ。入れないことにした。
  - 輪郭をちょうど外形線に合わせると、頭の飾りの三角形がつぶれた（45° で1つ）。外形線の点の角度を 1.15 倍、内側にした。
