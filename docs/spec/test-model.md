# 固定テストモデル

AI を使わずに Unity 側の正しさを確かめるための、手作りの顔のモデル。[中間形式 v0](intermediate-format.md) で保存し、PoC-04 以降の自動テストで常に同じ入力として使う。

- 場所：[`format/samples/test-face/`](../../format/samples/test-face/)
- 生成コード：`format/python/src/ugokue_format/face_model.py`（絵は `raster.py` で描く）
- 生成コマンド：`uv run --project format/python ugokue-format make-test-face format/samples/test-face`

## 作り方と権利

テクスチャは、生成コードの中で図形（楕円、多角形、2次ベジェ曲線）を塗って描く。外部の画像や素材は使わない。そのため、権利はこのリポジトリのコードと同じ扱いになる。

生成は決定的で、何度実行しても同じバイト列になる。浮動小数点の計算には四則演算と平方根だけを使い、座標は小数第2位で丸める。コミット済みのフォルダが生成結果と一致することを、CI の `test_test_face_regenerates_byte_identically` で確かめる。

モデルを変えるときは生成コードを変えて再生成し、同じ PR でこのページと、このモデルを期待値に使うテストを更新する。フォルダ内のファイルを直接編集しない。

## パラメータ

| パラメータ | 範囲 | 初期値 |
| --- | --- | --- |
| `AngleX`、`AngleY`、`AngleZ` | -30〜30 | 0 |
| `EyeOpenL`、`EyeOpenR` | 0〜1 | 1 |
| `MouthOpenY` | 0〜1 | 0 |
| `Breath` | 0〜1 | 0 |

すべてのキーフォームグループで、初期値の格子点の移動量は 0 になる。初期値のときの形は、メッシュの `vertices` そのものになる。

## 変形

### 顔の向き（AngleX × AngleY）

`head` の子孫のメッシュ（`body` と `neck` 以外のすべて）が、`AngleX`、`AngleY` の格子 `[-30, 0, 30]` × `[-30, 0, 30]` のキーフォームグループを1つずつ持つ。

各頂点に奥行き z（手前が正）を与え、頭の中心のまわりに yaw → pitch の順で回転したときの画面上の位置との差を移動量にする。

- x' = x cos(yaw) + z sin(yaw)
- y' = y cos(pitch) − (−x sin(yaw) + z cos(yaw)) sin(pitch)

x、y は頭の中心からの相対位置。奥行きは次のとおり。

| パーツ | 奥行き z |
| --- | --- |
| 顔、目（白目、黒目）、口の中、歯 | 0.5 √(120² − x² − y²)（半径 120 の球を奥行き方向に半分にした楕円体。根号の中が負なら 0） |
| まぶた、眉、口、鼻、前髪、横髪 | 上の値に、それぞれ +2、+4、+1、+18、+14、−6 を足したもの |
| 耳 | −30（一定） |
| 後ろ髪 | −35（一定） |

### まばたき（EyeOpenL、EyeOpenR）

格子は `[0, 1]`。1 で移動量 0（開いた目）、0 で閉じる。

- 白目と黒目：各頂点を y = 250 の線に向けて、距離の 92% だけ寄せる
- まぶた：中央の列を 16、左右の列を 6 だけ下げる

### 口の開き（MouthOpenY）

格子は `[0, 1]`。0 で移動量 0（閉じた口）、1 で開く。

- 口の中と歯：テクスチャは開いた形で描いてある。基準の形は、y = 304 を中心に縦を 0.1 倍につぶしたもの。1 で、テクスチャどおりの形に戻す
- 口（唇の線）：8 だけ上げる
- 顔（あご）：`face` メッシュに2つ目のグループ（`jaw_open`）を置く。一番下の行を 8、その上の行を 3 だけ下げる。顔の向きのグループと加算合成される

### 手続き的な動き

| 種類 | パラメータ | パーツ | 量 |
| --- | --- | --- | --- |
| rotate | `AngleZ` | `head`（中心は首の付け根 (256, 330)） | 1 あたり 1 度 |
| translate | `Breath` | `body` | 1 あたり (0, −3) |

## ビュー

顔の向きの格子と同じ 9 つの向き（yaw、pitch ∈ {−30, 0, 30}）のビューを持つ。ID は `front`、`left`、`right`、`up`、`down`、`up-left`、`up-right`、`down-left`、`down-right`。

顔の陰に隠れる耳を `visible: false` にする。

| yaw | 隠す耳 |
| --- | --- |
| 30（画面の右を向く） | `ear_l` |
| −30 | `ear_r` |

## 対応づけ

すべて `source: "manual"`、`confidence: 1`。位置は、顔の向きの変形と同じ計算で求める。

- 特徴点：眉、目の外側・中央・内側、鼻先、口の両端と中央、顔の左右の端、あご、耳の 17 点を、各ビューに持つ。隠れた耳の特徴点は、そのビューには置かない。
- 頂点の対応：`face` メッシュの全頂点を、`front` 以外の 8 ビューに持つ。位置は、そのビューの角度のキーフォームを適用した頂点位置と一致する（PoC-10 の対応づけの正解として使える）。

## テスト

[CI のテスト](ci.md) の Format tests と Unity EditMode tests で、次を確かめる。

- 検証ツールを通る
- 生成結果がコミット済みのフォルダとバイト単位で一致する
- Python と C#（.NET、Unity）で読み込んで書き出すと、元と一致する
- 上に書いたパーツ、キーフォーム、ビュー、対応づけを持つ
