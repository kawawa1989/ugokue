# 0010 頂点ごとの奥行きによる前後関係の判定は見送り、描画順とビューの切り替えのままにする

- 状態：採用
- 日付：2026-10-31

## 背景

[ADR 0005](0005-seamless-view-switching.md) で、角度による描画順の入れ替えと表示・非表示は、境界で見た目が一致するビューの切り替えだけで表すことにした。この方式では、頬の前の髪が輪郭の外へ出て顔の後ろに隠れていくような、連続的な前後関係の変化は表せない。そこで、頂点ごとの奥行き（z）で画素ごとに前後を決める方式を、参照レンダラーで試作して比べた（#27）。

試作は `dotnet/Ugokue.Core.Tests/Rig/DepthPrototype/` にあり、次のものを比べた（詳しくは[実行時の変形と描画](../spec/runtime-deformation.md#頂点ごとの奥行きの試作)）。

- 奥行き：固定テストモデルの[顔の向きの表](../spec/test-model.md)の奥行き（半径 120 の球の 0.5 倍＋パーツごとのかさ上げ）を、頭の中心のまわりに回したもの。首と体は回さない。
- 並べ方：描画順だけ、奥行きだけ、パーツごとのかさ上げ、頂点ごとのかさ上げ。かさ上げは、正面で描画順と同じ前後になる最小の値に余裕（マージン）を足したもの。
- 重ね方：画素ごとに断片を並べて重ねる方法（正確、A バッファ）と、GPU で一般的な深度の事前描画（不透明度 0.5 以上の断片だけが深度を書く）。

結果は次のとおり。

| 試したこと | 結果 |
| --- | --- |
| 奥行きだけで並べる | 正面で 9845 画素が今の絵と変わる。横髪は顔の表面より奥にあるが顔の上に描くなど、アニメの重ね順は物理的な奥行きと一致しない |
| かさ上げ（余裕 1） | 正面は一致する。奥の横髪は 30° で頬の後ろに回る（見える画素 3712 → 3248）。ただし、上を 1° 向いただけで後ろ髪が首と体より手前になり、8180 画素（全体の 3% 超）が一度に変わる。頭と一緒に回らないパーツとの境目で、前後が一度に入れ替わる |
| かさ上げ（余裕 5） | ±30° のスイープでちらつきも大きな変化もない（1° あたり最大 5824 画素）。ただし奥の横髪の見える画素は 3683 で、今の方式とほとんど変わらない |
| 深度の事前描画 | 正面で 744 画素が、断片を並べて重ねた結果と食い違う。半透明の縁が深度を書かないため |

## 決定

1. 頂点ごとの奥行きで画素ごとに前後を決める方式は採用しない。中間形式は変えない。
2. 前後関係は、今までどおり描画順とビューの切り替え（ADR 0005）で表す。
3. 頭の 3D の形（#39）は、絵を作る段階で使う。3D の形から各ビューの描画順と表示・非表示を決め、ADR 0005 の境界の一致の検査で確かめる。
4. 試作は、テストとしてリポジトリに残す。角度の範囲を ±45° より広げるとき（真横に近い向き）に、もう一度検討する。

## 理由

- **かさ上げの余裕を決められない：** アニメの絵を正面で崩さないには、パーツごとか頂点ごとのかさ上げが要る。余裕が小さいと、回したときに前後が一度に入れ替わり、急な変化になる。余裕を急な変化が出ないところまで大きくすると、前後は描画順とほとんど同じになり、画素ごとに決める利点が残らない。
- **重ね方の費用：** 半透明の縁や毛先を正しく重ねるには、画素ごとに断片を並べる方法（順序に依存しない半透明の描画）が要る。GPU で一般的な深度の事前描画では、縁で食い違いが出る。Unity の自前ランタイムで並べる方法を実装すると、描画の費用と複雑さが大きく増える。
- **メッシュの粗さ：** 前後が入れ替わる線は三角形の上の直線になるので、今のメッシュの粗さでは角張って見える。
- **奥行きの出どころ：** AI の奥行き推定（ロードマップの「体の前後」）の結果も、アニメの重ね順と一致する保証はなく、同じかさ上げの問題が残る。3D の形は、絵を作る段階でビューの描画順と表示・非表示を決めるのに使えば、実行時の処理を増やさずに済む。
- **ビューの切り替えで足りる：** ±45° までなら、隠れていくパーツは描画順を奥にしておけば輪郭に自然に覆われる（ADR 0005）。

### 採用する場合の中間形式の案（記録）

もう一度検討するときのために、試作で使った形を残す。

- メッシュに `depths`（頂点ごとの奥行き。キャンバスの画素と同じ単位で、手前が正）を足す。
- キーフォームの移動量を、x、y、z の3成分にする（奥行きも角度で補間する）。
- パーツに描画順と同じ前後を保つためのかさ上げを持たせる。正面の絵から、頂点ごとに求められる。
- 頭と一緒に回らないパーツ（首、体）との境目は、かさ上げとは別の扱い（たとえば、前後を描画順で固定するパーツの組）が要る。
- 中間形式の MINOR を上げる。

## 影響

- 中間形式、ランタイム、参照レンダラーは変えない。
- 試作のテスト（`DepthOrderingTests`）は CI で動かし、上の結果を保つ。角度の範囲を広げる検討の出発点にする。
- 頭の 3D の形（#39）は、絵を作る段階で各ビューの `overrides` を決めるのに使う。
