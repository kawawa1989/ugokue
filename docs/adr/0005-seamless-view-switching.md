# 0005 ビューの切り替えは境界で見た目が一致するときだけ使う

- 状態：提案
- 日付：2026-10-31

## 背景

[中間形式 v0](../spec/intermediate-format.md) では、描画順の入れ替え、表示・非表示、メッシュの差し替えをビュー（角度ごとの絵）単位で持ち、実行時は最も近いビューのものを使う（[ADR 0004](0004-intermediate-format-v0.md)）。ADR 0004 では、境界での破綻を抑える方法を PoC-05 以降で決めることにしていた。

PoC-05 の角度スイープ動画で、2つの問題が見つかった。

- ビューが切り替わる角度（±15°）を越えた瞬間に、奥の横髪が顔の後ろへ一度に回り、「髪がパッと消える」ように見えた。
- 境界の前後で隣のビューを混ぜるフェードも試したが、顔の上に半透明の髪が数度のあいだ見え、これも不自然だった。

## 決定

1. ビューの `overrides` による切り替え（描画順、表示・非表示、メッシュ）は、境界の角度で、切り替えの前後の見た目が一致する場合だけ使う。たとえば、隠すパーツや描画順を変えるパーツが、境界の角度ですでにほかのパーツに完全に覆われている場合。
2. 実行時は、最も近いビューで切り替える方式のまま変えない。フェードはしない。
3. 見た目の一致は、境界のすぐ手前とすぐ先（±0.001°）を参照レンダラーで描き比べて確かめる。固定テストモデルでは CI のテストにする。AI が作るモデル（PoC-11 以降）でも、生成後の検査として使う。
4. 頂点ごとの奥行きで画素ごとに前後関係を決める方法は、角度の範囲を広げる段階で検討する。

## 理由

- **フェードしない：** 切り替えの前後で見た目が違う限り、フェードはその違いを数度に引き延ばすだけで、途中の半透明の状態が新たな不自然さになる。
- **境界で一致させる：** 見た目が一致していれば、切り替えは目に見えない。その点で、Live2D などで手作業のモデルが角度による差し替えを目立たせない作り方と同じになる。実行時の処理を増やさずに済み、検査も単純になる（境界の前後を描き比べるだけ）。
- **横髪の入れ替えをやめる：** 頬の前に垂れている髪は、顔を 30° 回しても頬の手前に見えるのが自然で、顔の後ろに回すこと自体が誤りだった。顔の後ろに隠れていくべきものは、描画順を顔より奥にしておけば、変形に合わせて輪郭に自然に覆われる。
- **頂点ごとの奥行きを後にする：** 物理的には最も正しいが、中間形式の変更（MINOR を上げる）と、半透明の縁の扱いなどの課題がある。AI の奥行き推定と合わせて検討するほうがよい。

## 影響

- ビューの絵を作る側（AI の生成パイプライン、編集画面）は、境界で見た目が変わらないように `overrides` を置く。満たせない切り替えは、検査で見つかる。
- 境界の前後の描き比べは、ビューの格子の境界線（隣り合うビューの中間の角度）の上で行う。
