# 0012 顔の向きの出来は、生成した参考の絵と数値からエージェントが判定し、イラストごとの値を直す

- 状態：採用
- 日付：2026-10-31

## 背景

顔の向きのキーフォームは、頭の3D形状を回して作る（[ADR 0011](0011-face-rotation-by-head-3d-shape.md)）。形の値は全イラスト共通の定数で、出来の確認は人がシートや Unity で見ていたため、確認と修正のやりとりが多かった。同じ考え方のツール mesh-avatar-studio（MIT）は、決まったポーズを描き出し、エージェントが合格条件に沿って判定し、最大3回まで直す流れを使っている。

## 決定

- 頭の3D形状と回し方の値を `HeadParams` にまとめ、イラストごとの `params.json` で変えられるようにする。
- ±45° の向きの絵を Qwen-Image-Edit で生成し、**参考**として、モデルと並べたシートを作る。判定は「同じ向きに回って見えるか」と「破綻がないか」の2項目に分ける。
- 機械で測れるもの（描かれている三角形の伸びの分布、顔の外に出た特徴の頂点の数、特徴点から求めた向きの値の比）は数値で渡し、見た目の判断だけをエージェントに任せる。
- 判定の結果は決まった JSON に書き、形と整合をコードで確かめる。判定と調整は1枚につき最大3回で、直らなければ止めて人に報告する。
- まずは Claude Code などのエージェントが手順書（[エージェントによる顔の向きの判定](../spec/agent-review.md)）に沿って動かす。

## 理由

- 生成した絵は指定より横顔に寄り、顔立ちも変わる（PoC-09）。画像の差や特徴点の距離で一致を求めると、生成の癖に合わせてしまう。向きの方向と破綻の有無なら、参考として使える。
- 数値だけでは、あごの輪郭のぎざぎざや前髪のずれのような見た目の破綻を拾えない。画像だけをエージェントに見せると、伸びの量や輪郭からのはみ出しを見落とす。両方を渡す。
- 伸びは、透明な縁の三角形を含めると極端な値が多く出て、見た目と合わない（#39 の記録）。描かれている三角形だけを数える。
- パイプラインから API でモデルを呼ぶ方法は、API キーの扱いと費用が増える。手順が固まるまでは、開発で使っているエージェントが動かす。
- 選ばなかった方法：
  - 生成した絵を正解として、キーフォームを当てはめる（PoC-10 の方法）。生成の癖まで写し、破綻が多かった（ADR 0011）。
  - 回数の上限なしに直し続ける。値で直らない症状（分解の欠けなど）で終わらなくなる。

## 影響

- `keyforms` は、`params.json` がなければ既定値で書き、あればその値で作る。使った値は `evaluation.json` に残す。
- 判定の材料は `artifacts/keyforms/<イラスト名>/review/` に、判定の結果は同じ場所の `review-<回数>.json` に置く。
- 値の名前や意味を変えるときは、手順書の「症状と直す値」も同じ PR で直す。
- パイプラインからの自動の判定は、手順が固まってから検討する。
