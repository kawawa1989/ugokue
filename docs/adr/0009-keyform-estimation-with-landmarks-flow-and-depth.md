# 0009 顔の向きのキーフォームは、特徴点・オプティカルフロー・層の奥行きから推定する

- 状態：採用
- 日付：2026-10-31

## 背景

PoC-10 では、PoC-09 で生成した向きの絵と、PoC-08 の分解結果から作ったパーツを対応づけ、顔の向きのキーフォームを推定する。生成した絵には次の性質がある（[向きと表情の差分の生成](../spec/view-generation.md#実機の結果)）。

- 顔の大きさと傾きが、正面の絵からずれている（大きさ 0.6〜1.0 倍、真上を向く絵でも ±20° 前後の傾き）。
- 髪の流れや耳など、細かい形が絵ごとに描き直されている。
- アニメ絵はベタ塗りが多く、塗りの内側には模様がない。

対応点の求め方の候補は、特徴点とオプティカルフロー（CPU）、深層学習の密な対応推定（GPU）、向きの絵もパーツに分解して形を合わせる方法、の3つだった。

## 決定

- 対応点は、anime-face-detector の特徴点と、OpenCV のオプティカルフロー（DIS）で求める。特徴点で大きさと傾きをそろえ、薄板スプラインでおおまかに合わせ、フローで細かく合わせる。往復のずれから信頼度を付ける。
- 大きさと傾きの補正は、正面の特徴点を硬い楕円体として回した位置に、向きの絵の特徴点を相似変換で合わせて求める。
- 頂点の移動量は、信頼度で重み付けした対応点、となりの頂点との差（滑らかさ）、予測の3つの項を最小にして解く。正面の絵でそのパーツが見えていない頂点には、対応点を使わない。
- 予測は、顔のパーツでは特徴点の薄板スプライン（特徴点から遠いところは楕円体の動き）、髪・耳・頭の飾りでは See-through の層の奥行きで頭を回した動きにする。髪・耳・頭の飾りでは、生成した絵の対応点を弱めにしか使わない。
- 前髪（顔の層より手前のパーツ）は、層で一定の奥行きではなく、頭の楕円体の表面に沿わせる。頭の楕円体は、顔の層（髪の下に補完された頭皮を含む）と前髪の範囲から決める。
- 顔の層の、特徴点から遠いところ（補完された頭皮）は、前髪と同じ楕円体の動きに強く寄せる。
- 奥行きから作った予測と顔の層では、滑らかさを予測からのずれにかける。顔の中のパーツ（目、口など）と、裏返って解き直すときは、移動量そのものにかける。
- 変換のメッシュは、四角形1枚から、不透明な部分を覆う格子に変える。
- 評価は、C# の参照レンダラーで描いた絵と、補正した向きの絵を比べる。固定テストモデルの手作りのキーフォームを正解とした比較を CI で行う。

## 理由

- 特徴点とフローは GPU を使わず、固定テストモデルでの正解との比較を CI で回せる。深層学習の対応推定は写真で学習したもので、アニメ絵での精度が分からない。向きの絵の分解は、GPU で約5時間かかり、向きごとに分解の結果が揺れるおそれがある。
- 大きさと傾きを取り除かないと、横を向くたびに頭が縮んだり傾いたりする。硬い頭として回した位置に合わせれば、向きによる見かけの変化を残したまま、画像編集モデルが加えたずれだけを取り除ける。
- 最初は、すべてのパーツで特徴点の薄板スプラインを予測にした。顔の中のパーツはよく合ったが、髪は横向きで引き伸ばされて崩れ、後ろ髪は変形しない場合より正解から離れた。後ろ髪や耳は頭の奥にあって顔と逆向きに動くのに、顔の動きをそのまま延ばしていたため。層の奥行きで回す予測に変えると、固定テストモデルで髪と耳の誤差が半分以下になり、実際のイラストでも髪の崩れがなくなった。
- 生成した絵の髪は描き直されているので、対応点に強く合わせると、正面の髪の絵が引き伸ばされる。
- 人の確認で、横向きと下向きで前髪の根元の横や上に肌色が見えた。前髪を層で一定の奥行きで回していたため、頭頂の生え際まで顔より大きく動き、See-through が髪の下に補完した頭皮（顔の層）がはみ出していた。前髪を頭の表面に沿わせると、生え際は頭皮と一緒に動く。特徴点から決めた楕円体は頭頂まで届かないので、層の範囲から決める。
- 移動量そのものに滑らかさをかけると、頭の表面に沿った予測のように場所によって違う動きがならされる（固定テストモデルの前髪で、予測 5.6 px に対し解は 15.5 px）。一方、薄板スプラインの予測の形を残すと、実際のイラストで口やまぶたが極端に伸び縮みした（極端な伸びの角度が 0〜1 から 100〜186 に増えた）。
- ベタ塗りの内側でフローの信頼度を下げる方法も試したが、固定テストモデルで改善しなかったので入れていない。

## 影響

- キーフォームの推定には、分解結果（層の奥行き）と、向きの絵の特徴点が必要になる。
- 変形したモデルの向きの変化は、生成した絵より控えめになる。生成した絵に新しく描かれた耳や横顔の輪郭は、正面のパーツの変形では出せない。必要なら、角度別のメッシュへの切り替え（ビュー）を後で加える。
- 顔の向き以外のキーフォーム（閉じ目、口開け）は、このやり方では作っていない。
- 細かい数値（滑らかさ 2、予測の重み、奥行きの換算、補正の範囲など）は仮の値で、人の確認で調整する。
