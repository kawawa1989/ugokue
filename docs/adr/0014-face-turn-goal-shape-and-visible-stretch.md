# 0014 斜めの顔は目標の絵の形に合わせ、伸びは見えている三角形で測る

- 状態：採用
- 日付：2026-11-01

## 背景

#50 で輪郭の目標の線（[ADR 0013](0013-face-outline-by-2d-target-line.md)）を入れたあとも、±45° の顔はレビュー役（[ADR 0012](0012-agent-review-of-face-rotation.md)）の判定で破綻が不合格のままだった（#52）。

- 手前の目が正面より広がり、奥の目がつぶれた。
- 奥側の頬は一本の斜めの直線で、あご先が尖り、口の高さで段ができた。
- 伸び（`maxP99` 2.0 超、`minP1` 0.3 未満）が、どの値でも基準に入らなかった。

人から、01-long-straight の顔の角度だけを変えた目標の絵（画像生成）を渡され、まず ±45° でこの形に破綻なく作ることを目標にした。

## 決定

1. 既定値は、目標の絵の特徴点（目と口の間の長さで測った、奥の目の幅、鼻先・口・あご先の横のずれ、奥側の輪郭の位置）に合わせて選ぶ。判定の基準（`nearEyeWidth`、`farToNear`、`farEyeGap`、`cheekBulge`）も、目標の絵の形に合わせる。
2. 目は、手前の目を横に広げない（正面の幅が上限）。黒目は向いた側へずらす（`irisGaze`）。
3. 手前側（頭の横が回ってくる側）の並べ直しは、中心から輪郭までの全体で行い、頭の横が広がるぶんを散らす。口より下では、描かれたあごの縁を、断面の端ではなく板の上の奥行きで回す。
4. 奥側（向いた側）の輪郭の合わせ直しは、口より下では描かれたあごの縁から外形線へ詰める。
5. あごの線は、口より下の顔の層の端をならしすぎず、描かれた線のまま目標の線へ寄せる。奥側の頬からあご先への曲線は、頬のふくらみのいちばん強い行から始め、あご先へ横向きに丸く入れる。
6. 伸びの数値は、その向きで手前に描かれるパーツに隠れて見えない三角形を数えない。`face` の段階は、顔の段階で見るパーツだけの伸び（`faceStretch`）で判定する。

## 理由

- 目標の絵があれば、「自然かどうか」を特徴点の値で比べられる。レビュー役の判定だけでは、値の選び方が回ごとに揺れた。目標の絵は正解ではないが、向きと立体の見え方の手がかりになる。
- 伸びの大きい所を三角形ごとに調べると、値ではなく、手順の継ぎ目にあった。
  - 手前側の並べ直しの始まりの位置（中心から 0.3 × 半幅）で、伸びの比が折れていた。
  - 口の行の上下で、輪郭の点の奥行きが急に変わっていた。
  - 奥側では、口より下の断面の端を外形線へ詰めたため、描かれた縁の近くが押し込まれていた。
  - これらは値を変えても動かないので、コードで直した。
- あご先が尖るのは、行ごとの端をならすと、V 字のあご先の近くで端が外へ広がり、寄せても描かれた縁が内側に残るためだった。
- 奥側の頬が左右で違って見えたのは、曲線を「目標の線がいちばん外の行」から始めていたため。顔の層の縁の傾きによっては、その行が目の高さになり、足した頬のふくらみが消えた。
- 前髪の下に補完した頭皮は、立体として正しく強く縮む。しかし、髪を付けると見えない。見えない所の縮みで不合格にすると、見えている形を壊してまで直すことになる。

## 影響

- 既定値：
  - `headDepth` 0.85、`facePlate` 0.6、`noseProtrusion` 0.25、`chinPlate` 0.22、`cheekBulge` 0.03、`irisGaze` 0.15
  - あごの曲線の、あご先の側の制御点 0.1
- `metrics.json` の各向きに `faceStretch` が加わる。`stretch` と `faceStretch` は、隠れて数えなかった三角形の数（`hidden`）を持つ。
- 01-long-straight は、`face` の段階で6つの向きすべてが合格した（`headDepth` 0.85、`cheekBulge` 0.03、`chinPlate` 0.16、`pitchScale` 0.8）。
- 02〜05 は、レビュー役の判定をしていない（#54）。
  - 02 の奥の目が輪郭で欠ける。
  - 03 の伸びが基準を外れる。
  - 01 の `full` の段階はまだ判定していない（#53）。
- 目標の絵は 01 の1枚だけなので、ほかのイラストの形が目標に近いかは確かめていない。
