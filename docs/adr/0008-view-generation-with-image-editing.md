# 0008 向きと表情の絵は、頭の周りを切り出して画像編集モデルに指示文で変えさせ、分解結果のマスクで頭だけを戻す

- 状態：採用
- 日付：2026-10-31

## 背景

PoC-09 では、テストイラストごとに、顔の向き 3×3（AngleX ±30°、AngleY ±20°）と、閉じ目・口を開けた絵を生成する。体と背景は動かさず、頭だけを変える。PoC-10 で、これらの絵とパーツを対応づけて変形を推定する。

候補の画像編集モデルは次のとおり。

- Qwen-Image-Edit-2511（Apache-2.0）。被写体の周りをカメラで回す追加学習（Multiple-Angles LoRA、Apache-2.0）がある。
- FLUX.1 Kontext。顔立ちを保ちやすいという報告があるが、dev 版は非商用のライセンス。
- Qwen-Image 2.1。生成と編集が1つになった新しい版だが、ライセンスが変わったという報告があり未確認。

## 決定

- 画像編集モデルは Qwen-Image-Edit-2511 を bf16 で使う（Modal の A100 80GB）。
- 向きは、Multiple-Angles LoRA を使わず、指示文（「頭だけを画面の右へ約30°向ける。体、服、髪型、絵柄、背景はそのまま」など）で指定する。
- イラスト全体ではなく、PoC-08 の分解結果の顔の層の箱を広げた範囲（頭と首の周り）を切り出して編集する。
- 生成した絵は、分解結果から作った頭の範囲のマスク（髪、顔、目、耳、頭の飾りの層のうち、見えている画素。あごの少し下まで）の部分だけを使い、外側は元のイラストに戻す。
- 生の生成結果について、頭の範囲の外がどれだけ変わったかを記録する。
- 向きは、anime-face-detector で28点の特徴点を検出し、正面の絵からの目と鼻の位置の変化で、指定した向きを向いているかを判定する。
- 指示文、乱数、モデルの版は `pipeline/samples/views.json` と生成結果の記録に残す。

## 理由

- Qwen-Image-Edit-2511 は、ライセンスが商用に使え、向きを変える編集の実績がいちばん多い。
- Multiple-Angles LoRA は、カメラを被写体の周りに回すので体ごと回り、角度も 45° 刻み。頭だけを ±30°・±20° 回すという目的に合わない。
- 指示文で「体はそのまま」と書いても、画像編集モデルは向きを変えるときに体の向きや手の位置まで描き直す（01 で、頭の範囲の外の不一致が 17〜31%）。頭の周りだけを渡せば、モデルから体がほとんど見えないので、体を回しにくい。
- 頭だけを戻せば、体の絵は元のイラストと画素単位で同じになり、PoC-10 の対応づけが頭だけで済む。
- マスク付きの編集（inpaint）も考えたが、回した頭がマスクからはみ出せず、Qwen-Image-Edit-2511 の重みで使えるかも未確認なので選ばなかった。
- 頭の範囲は、PoC-08 の分解結果の層からそのまま作れる。
- 特徴点は、アニメ絵で学習した anime-face-detector を使う。人の写真用の検出器は、アニメ絵の目や鼻をうまく捉えない。

## 影響

- 向きと表情の絵を作るには、そのイラストの分解結果（`decompose_images` の出力）が先に必要になる。
- 頭が大きく動くと、マスクの外にはみ出した髪が切れる。あごの下のマスクの境界では、髪の流れが切り替わって見えることがある。マスクの範囲は、人の確認で調整する。
- Qwen-Image-Edit-2511 の bf16 は VRAM を約 60GB 使うので、手元の 16GB の GPU では FP8 や GGUF の量子化が必要。そのバックエンドを作るときに、画質の違いを確かめる。
- anime-face-detector は古い mmcv-full 1.x 系に依存する。Modal では Python 3.11 と mmcv-full 1.7.2 で動かし、mmpose の版の上限の確認だけを緩めている。
