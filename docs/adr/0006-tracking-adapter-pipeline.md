# 0006 入力アダプターは、顔を見失ったら値を保持し、ゆっくり戻す

- 状態：採用
- 日付：2026-10-31

## 背景

PoC-07 では、nizima LIVE から届いた値をモデルのパラメータに変換する。PoC-06 で記録した実機のデータから、次のことが分かった（[nizima LIVE からの受信](../spec/nizima-live.md#実機の結果)）。

- 顔を見失うと（`FaceFound` が 0 に近づく）、目と口の値は数フレームで初期値に戻り、角度はゆっくり初期値に向かう。
- 顔を見失う時間は、0.2 秒程度の短いものから 10 秒を超えるものまである。
- 顔を捉え直すと、角度が 0.2 秒で 20° ほど動く（見失っていたあいだの実際の向きに戻る）。
- 値は `GetLiveParameters` の範囲を超えることがある。
- 通知は nizima LIVE の描画 fps（30 または 60）ごとに届き、アプリは 60 fps で描画する。

nizima LIVE の値をそのまま使うと、顔を見失った瞬間に目が開き、口が閉じ、捉え直した瞬間に頭が跳ねる。

## 決定

入力アダプターは、1フレームごとに次の順で値を作る。

1. **入力の有無の判定**：入力元ごとに「顔を捉えているか」を表す値（nizima LIVE では `FaceFound`）を決め、0.9 以上の通知だけを有効とする。最後の有効な通知から 0.2 秒たったら、入力が途切れたとみなす。通知そのものが止まった場合（nizima LIVE の終了など）も同じに扱う。
2. **変換**：有効な通知の値から校正の値を引き、入力の範囲をパラメータの範囲に線形に置き換え、パラメータの範囲（上限・下限）に収める。
3. **途切れたとき**：途切れてから 1 秒は、最後の有効な値を保持する。それを過ぎたら、時定数 0.5 秒でパラメータの初期値へ戻す。
4. **復帰したとき**：入力が戻ってから 0.5 秒は、時定数 0.12 秒の遅い平滑化をかけ、跳ねずに今の値へ近づける。
5. **平滑化**：指数平滑化を使う。強さ `s` は「1/60 秒あたりに前の値を残す割合」とし、経過時間 `dt` 秒では前の値を `s^(60·dt)` の割合で残す。これにより描画の fps によらず同じ速さで追従する。`s` はモデルの `tracking.parameters[].smoothing`、なければ 0.5（時定数約 24 ms）。

校正は、今の有効な値を「正面」として覚える。対象は角度だけで、目と口は校正しない。

入力元は `ITrackingSource`（最新のフレームを返す）で差し替える。nizima LIVE のクライアントと、記録したデータの再生がこれを実装する。

## 理由

- 顔を見失っているあいだの nizima LIVE の値は、本人の動きではない。保持すれば、短い見失いではモデルがまったく動かず、配信の見た目が崩れない。
- 長く見失ったときに保持し続けると、横を向いたまま固まって見えるので、ゆっくり正面に戻す。
- 復帰の跳ねは、本人の動きとしては正しいが、見失っていたぶんの動きがまとめて出るので不自然になる。復帰の直後だけ遅くすれば、ふだんの追従の速さを犠牲にしない。
- 平滑化の強さを「1フレームあたり」で決めると、30 fps と 60 fps で追従の速さが変わる。時間あたりで決めれば、描画の fps を変えても見た目が変わらない。
- 線形補間でフレームの間を埋める方法は、1フレーム分の遅れ（30 fps で 33 ms）が必ず増えるので選ばなかった。指数平滑化なら、遅れは時定数（約 24 ms）程度で済む。

## 影響

- 保持・復帰・平滑化の数値（0.9、0.2 秒、1 秒、0.5 秒、0.12 秒、0.5）は仮の値で、人の確認（遅れやもたつき）で調整する。調整しても決定の構造は変えない。
- 入力元を追加するときは、`ITrackingSource` と、入力元の名前からパラメータへの変換表（プロファイル）を用意する。
- 実装の詳細と数値は [入力アダプター](../spec/tracking-adapter.md) に書く。
